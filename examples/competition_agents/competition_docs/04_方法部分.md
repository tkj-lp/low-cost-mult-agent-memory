# 方法部分

## 1. 方法总览

本系统从三个层面改造传统多 Agent 协作流程：

1. 通信层：从自然语言长文本切换到结构化协议包
2. 状态层：支持 embedding 与 hidden state 的非文本中间状态传递
3. 记忆层：引入 evidence memory 与 experience memory，实现跨任务复用

## 2. 纯文本协作基线

在 `baseline_text` 模式下：

- Agent 间通过自然语言文本传递上下文
- 中间状态主要以文本形式展开
- 共享记忆写入以摘要和证据为主

该模式用于作为对照基线，衡量结构化通信和非文本状态传递带来的收益。

## 3. 结构化协议协作

在 `protocol_api` 与 `protocol_api_embedding` 模式下：

- Agent 间不再直接透传完整自然语言上下文
- 通信内容收敛为结构化包
- 包中包含动作、参数、结果、能力需求、状态引用和认知缺口等字段

这种做法有两个直接收益：

1. 减少文本通信字符开销
2. 降低接收 Agent 的解析成本

## 4. 非文本状态传递机制

### 4.1 embedding 路径

`protocol_api_embedding` 模式中：

- Planner / Retriever / Reasoner 的关键中间状态会被编码为 embedding
- 系统通过 `latent_state_ref` 引用这些非文本状态
- 后续 Agent 结合引用和少量摘要信息消费状态

该机制的重点不在于“替代所有文本”，而在于减少不必要的全文重复传递。

### 4.2 hidden state 路径

`latent_hidden` 模式中：

- 本地模型在生成计划或答案时提取 hidden state
- 系统以 `hidden_state_ref` 的方式进行状态交换
- 后续节点只传递引用和必要元数据，不重复传输大段文本

该机制体现了赛题要求中的“隐藏状态特征或其他中间表示直接交换”。

## 5. 共享记忆机制

### 5.1 evidence memory

evidence memory 用于保存：

- 最终答案摘要
- 支持证据
- 执行结果
- 可直接复用的事实片段

其核心作用是为后续任务提供事实支撑。

### 5.2 experience memory

experience memory 用于保存：

- 问题模式
- 解题策略
- 失败模式
- 触发条件
- 可迁移经验说明

其核心作用是为后续任务提供“如何选答案、如何避错”的规则卡片。

## 6. memory refine

与直接把 final answer 写进记忆不同，本系统在 Summarizer 阶段加入了 memory refine。

基本流程为：

```text
Task case
-> Distillation
-> Experience rule card
-> Experience memory write-back
```

当前 refine 输入包括：

- 当前问题
- 候选答案
- 最终答案
- 支持证据
- 是否答对
- 是否命中历史经验

输出包括：

- `problem_pattern`
- `solution_pattern`
- `failure_pattern`
- `trigger_conditions`
- `abstraction_note`

## 7. experience 复用闭环

当前闭环逻辑为：

1. 当前任务结束后写入 experience memory
2. 后续任务检索 experience memory
3. Retriever 将命中的经验规则单独整理为 `experience_rules`
4. Reasoner 显式消费这些规则
5. Summarizer 统计写入和复用情况

这使系统从“只缓存历史答案”升级为“复用历史经验规则”。

## 8. 受限 CodeAct 执行

在 CodeAct 场景中，系统支持：

- 让 Reasoner 形成执行请求
- 由 Executor 在受限 Python 环境执行
- 进行 AST 安全检查
- 返回结构化执行结果

该机制用于补足赛题鼓励项中的工具执行能力。

## 9. 当前方法特点总结

当前方法的核心特点可以总结为：

1. 有纯文本基线，便于和正式模式对比
2. 有结构化协议，体现低开销通信
3. 有 embedding / hidden 两类非文本状态传递
4. 有 evidence memory + experience memory 双层记忆
5. 有连续任务验证复用效果
