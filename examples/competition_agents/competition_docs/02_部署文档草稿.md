# 部署文档草稿

## 1. 文档目标

本文档用于说明项目部署方式、依赖要求、运行入口与后续 openEuler 环境适配注意事项。

当前文档为草稿版，已覆盖本地开发与预实验流程；正式交付前还需补充 openEuler 24.03-LTS-SP3 环境验证结果。

## 2. 环境要求

### 2.1 当前开发环境

当前开发阶段已在以下类型环境中进行过运行验证：

- Windows + Python 虚拟环境
- 本地 API 调用环境
- 本地 hidden model 推理环境

### 2.2 目标交付环境

赛题要求最终代码可在以下环境正常运行：

```text
openEuler 24.03-LTS-SP3
```

因此最终交付前，需要在该环境中补做：

- 安装验证
- 命令验证
- 正式实验复现
- 日志与结果留档

## 3. 代码目录

比赛原型位于：

```text
examples/competition_agents
```

重要子目录：

- `agents/`：多 Agent 逻辑
- `competition_agents/`：共享组件、状态、记忆、LLM 封装
- `hypergraph_memory_method/`：超图记忆实现
- `frontend/`：前端页面
- `data/`：实验数据集
- `tests/`：相关测试

## 4. Python 依赖

建议先创建虚拟环境，再安装项目依赖。

示例：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

如果仓库没有统一的 `requirements.txt`，则需按当前项目实际依赖安装：

- `pytest`
- `transformers`
- `torch`
- 以及项目运行所需的其它依赖

正式提交前建议补一个明确的依赖清单。

## 5. API 配置

正式 API 模式需要准备：

```text
examples/competition_agents/.env.local
```

关键变量示例：

```text
LLM_PROVIDER=openai_compatible
LLM_PLANNER_PROVIDER=openai_compatible
LLM_REASONER_PROVIDER=openai_compatible
LLM_SUMMARIZER_PROVIDER=openai_compatible
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-flash
LLM_API_KEY=你的真实 key

EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_API_KEY=可选；不配时默认复用 LLM_API_KEY
```

## 6. 本地 hidden model 配置

`latent_hidden` 模式依赖本地模型。

部署时需要确认：

1. 模型权重可被 `transformers` 正常加载
2. 本地缓存路径可访问
3. 如需 GPU，确认 `torch.cuda.is_available()` 为真

如果目标环境无 GPU，也可退回 CPU，但速度会明显下降。

## 7. 前端运行

前端服务入口：

```powershell
python examples\competition_agents\frontend_server.py --host 127.0.0.1 --port 8765 --echo-run-output
```

前端页面目录：

```text
examples/competition_agents/frontend
```

若前端开发环境需要单独启动 Vite，请按前端依赖说明执行。

## 8. 结果输出

正式实验结果统一通过：

```text
=== run_result_json ===
```

区块导出为前端可解析 JSON。

同时当前项目也支持将运行结果保存到：

```text
run_result/
```

目录下，便于后续查看与整理。
