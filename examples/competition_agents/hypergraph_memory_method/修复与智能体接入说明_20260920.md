# 记忆模块修复与智能体接入说明

基于提交 `43301ee`。本次修改严格限制在 `hypergraph_memory_method/`，包括实现、测试和本文档；没有修改智能体、运行器、数据集、前端或目录外的测试。

## 已完成的模块修复

| 问题 | 修复后的行为 |
| --- | --- |
| 类型过滤晚于截取，目标层可能被其他层挤出候选 | 五种检索模式都在召回排序前过滤类型与明确拒绝、归档状态 |
| 旧持久库重新加载绕过上游筛选 | 自动补入的持久记录仅限已核验、可正向使用的经验，不重新引入旧批次问答及问题经验 |
| 相同局部编号静默覆盖 | 检索入口拒绝重复编号并给出明确错误；不擅自重写调用方引用 |
| 经验合并忽略完整触发条件、失败约束和作用域 | 合并身份包含完整条件和审核状态；统一服务的维护分组也区分经验作用域 |
| 合并丢失部分知识和问答来源 | 合并保留全部来源编号、知识引用；已有批次维护测试继续验证来源归档和容量剪枝 |
| 每次查询对全部记忆重新分词 | 构建词项与标签倒排表；真实向量模式仍可能进行线性向量计算，不宣称已实现近似检索 |
| 所有候选都生成完整证据投影 | 仅为最终返回条目生成证据投影，回归测试验证调用次数与返回数量一致 |
| 哈希向量、异维向量被用作语义相似度 | 哈希不再贡献超图语义评分；纯语义模式在哈希配置下明确退回关键词检索；异模型或异维向量重新编码或不参与该通道 |
| 缓存遗漏向量、来源等变化；返回值可污染缓存 | 扩大失效依据，返回独立结果；合并经验的计数刷新汇总全部来源 |
| 先复制递归轨迹，再删掉大量历史 | 先压缩历史引用再复制，避免遍历随后被丢弃的递归记忆 |
| 同一问题多个检索步骤重复建图和抽取特征 | 有界缓存上下文图与文档特征；内容改变会失效；不同查询继续独立评分 |
| 已知标准答案被当作候选证据 | 对带有 `official_answer_annotation` 来源的输入明确报错，要求使用原始证据段落 |
| 旧结果缺少单独组编号而导致复用评估失配 | 可从带组前缀的任务编号恢复组信息；仍排除其他组的记忆 |

上下文缓存可通过公开接口 `clear_context_cache()` 清理。旧索引缓存继续使用 `clear_hypergraph_index_cache()`。两者都没有定时任务或后台线程。

## 必须交接的行为变化

1. **重复编号现在报错。** 编号按列表长度生成的问题位于目录外的 `competition_agents/memory.py:1423`，本次不能修改。调用方应使用统一记忆服务返回的全局编号；只改检索器不能无歧义地修复已经产生的重复引用。
2. **当前三组问答重写数据会被拒绝。** 它们将标准答案标成知识候选，并复制为支持段落。本次没有修改数据。需要数据准备方根据原始出处提供真实段落，而不是关闭检索入口的来源检查。官方证据片段仍可用于明确限定证据范围的组件测试。
3. **哈希不再作为语义通道。** 若要比较语义召回，需为各协作方法固定相同的真实嵌入模型，并为旧数据重建向量。哈希向量仅是接口占位，不具备语义相似性的依据。
4. **自动持久加载更严格。** 缺少核验状态的旧经验不会因为存在于数据库中就自动进入后续任务。调用方显式传入的旧格式内存记录仍保持兼容，但明确拒绝、归档、禁用的记录不能绕过过滤。

统一记忆服务的接入顺序：开始批次 → 写入知识 → 指定记忆层检索并保存检索回执 → 原子提交任务问答和候选经验 → 根据实际采用及外部核验登记反馈 → 结束批次。经验来源须用全局编号。不能把答案正确直接当成每条提炼规则都已核验。

接口细节见 [记忆服务交接文档](MEMORY_SERVICE_HANDOFF.md)。旧列表检索接口主要用于兼容，不能代替统一服务的命名空间、任务类型、批次隔离和事务维护。

## 验证结果

记忆目录测试：**98 项通过、1 项跳过**。格式检查、静态检查和差异空白检查通过。新增边界测试覆盖过滤时机、重复编号、持久重载、经验合并、向量一致性、缓存失效和隔离、证据投影次数、递归轨迹复制、答案来源检查等。

扩大到目录外的现有测试：**211 项通过、11 项失败、1 项跳过**。其中10项是修复前就存在的交接消息或配置约定不一致；另1项是旧测试要求默认哈希向量产生正的语义分数，与本次明确修正的语义契约冲突。目录外测试没有修改，所以没有把整体结果报告为全部通过。

## 局部耗时验证

同一进程内交替测量旧、新实现各25次，取中位数。旧实现取自提交 `43301ee`，索引查询对照共用当前的构图辅助函数；使用哈希配置、预先构建的索引，不含模型生成、索引构建、数据库读取和外层缓存签名计算。构造数据使用不同的纯字母实体名，确认查询非空命中且新旧返回编号一致。宽查询包含共有词，窄查询只含目标实体。它是局部性能检查，不是完整实验或独立样本显著性检验。

| 已缓存索引查询 | 记录数 | 修改前中位数／毫秒 | 修改后中位数／毫秒 |
| --- | ---: | ---: | ---: |
| 宽查询 | 10 | 2.1821 | 1.1739 |
| 窄查询 | 10 | 0.3823 | 0.4076 |
| 宽查询 | 100 | 24.1273 | 6.7920 |
| 窄查询 | 100 | 1.4308 | 0.4472 |
| 宽查询 | 500 | 137.2764 | 47.4842 |
| 窄查询 | 500 | 7.1259 | 0.4888 |

十条记忆的窄查询没有改善，略慢，不能宣称所有场景都加速。随着候选增多，避免重复分词和为未选候选生成证据投影的收益更明显。

另用现有主题切换第一组数据的首轮做相同输入的重复上下文查询：修改前2.0764毫秒、修改后0.4906毫秒，返回证据文本顺序一致。该结果含缓存收益，不代表新语料首次检索的速度。

**没有测量真实模型的端到端耗时，所以不能据此给智能体侧分配主要耗时比例。代码已确认智能体侧有额外前向、重复文本输入及可能的二次生成，但“主要耗时在哪边”还需在相同配置下记录规划、检索、隐藏表示、推理、修复、维护各阶段的墙钟时间。**
