# 固定协作方案

当前版本：`competition-v8.0-shared-final-answer-hybrid-lifecycle-20261001`。运行入口只有 `run_competition.py`，前端通过 `runner_server.py` 调用同一个入口。

| 前端选项 | 记忆组织 | 记忆检索 | 实际交接内容 |
| --- | --- | --- | --- |
| 纯文本 | 普通文本 | 相似度 | 累积的完整原文、角色输出和所召回的整轮记忆 |
| 协议字段 | 超图 | 超图跳跃 | 原始问题、模型生成的控制与候选答案、原样保留的来源关系字段 |
| 隐状态 | 超图 | 超图跳跃 | 同进程续接计算缓存和连续表示，仅最终输出生成文字 |
| AutoForm | 普通文本 | 相似度 | 模型自主选择格式生成的交接消息 |
| LLMLingua-2 | 普通文本 | 相似度 | 官方压缩模型处理后的交接消息 |

前三项是固定主要方案，后两项是保留对照。当前连续样本由用户指定截图中的 `data/official_factoid_ranked_topiocqa_003_10turns.json` 选取：第153号会话，原顺序完整十题。该窗口从原会话第一轮开始，后续涉及人物指代和作品话题承接；没有导入后续标准历史答案。题目已与官方原始文件逐字核验，来源说明见 `data/continuous_topiocqa_153_10turns_v1/provenance.json`。原三题目录保留用于历史复现。第119号会话及更早的小猫样本保留作历史记录。

纯文本记忆以完整一轮记录为相似度检索单元，不切句、不建立段落索引、不把命中内容再摘要。知识库仍保留完整原文；协议和隐状态读取预先建立的超图。三种实现拥有独立会话记忆，切换方案不会继承另一方案的状态。

协议的本地调用使用模型原生模板与生成接口，不加载隐状态、格式约束解码或跨角色缓存。第8.0版服务器已完成千问3.5九十亿参数模型的查询校准；切换模型或任务类型必须重新生成对应映射，不能直接沿用旧版本或使用在线文字接口。基础模型权重保持不变。

三种主要方式的最终角色共用同一份回答要求。隐状态采用完整缓存接续，不执行额外的末层反馈迭代。生命周期按角色消费者完成时间回收临时提示与边界，最近两轮回答保留；原问题、公共规则、来源事实和外部结果继续保留。混合模型只回收完整注意力层的到期条目，递归状态不按词元裁剪；回收会改变可访问的历史条目，不能称为语义无损。

项目两项主要贡献、最接近的已有工作、代码位置与实测依据见 [项目创新说明](docs/项目创新说明.pdf)。统一提示后的完整十题结果位于 `outputs/qwen35_ten_20261001/qwen35-ten-20261001-v80-v1`，固定来源的生命周期消融位于同级 `qwen35-lifecycle-20261001-v80-v1`。隐状态本轮35.49秒、答案覆盖度90%；容量与时间下降，但覆盖度仍低于纯文本，不能宣称全面达标。

隐状态经验层保留：从完成的检索中记录关系路径策略，在来源完整且遗漏候选的分数上界检查通过时缩小候选计算；否则回到完整检索。经验有数量上限与剪枝，不把参考答案写入经验，也不把检索等价性称为答案正确性验证。

## 指标边界

- 预备知识构建、校准和模型加载单列，不计入任务流程耗时；在线检索、角色处理、压缩和记忆写回计入。
- 文字方式报告真实交接消息的字节数；在线接口请求量与角色交接量不能混用。
- 隐状态报告每次交接所需的完整接续状态快照大小，包含各层缓存、隐藏表示及接续元数据。累计快照大小、缓存驻留峰值与网络实际传输是不同指标；同进程续接未进行网络传输实测，不能用引用长度或零字节证明载荷下降。
- 答案采用标准答案词元覆盖度；额外内容不扣分，少答部分计分。这不是自动事实核验，明确矛盾需要另做来源审查，不能把该分数直接称为事实正确率。
- AutoForm 目前每次交接额外调用同一模型转换格式，通常每题七次调用，转换时间全部计入。
- LLMLingua-2 必须加载官方模型，禁止以规则压缩兜底冒充该对照。

## 目录

- `competition_agents/methods`：五个独立入口和统一执行器。
- `config`：前后端共同方法配置、版本文件校验清单。
- `data`：连续任务、原始来源、固定预备知识和既有校准。
- `tools`：离线准备及固定版本核验工具。
- `hypergraph_memory_method`：底层记忆库。比赛运行入口只开放上述两种检索。
- `docs/evidence`：必要的历史原始结果，含失败与无提速对照。
- `docs/history`：历史报告，里面的旧运行路径不再作为当前入口。
- `runtime`：新运行产物，已排除出版本管理。

启动和复核见 [运行手册](RUNBOOK.md)。清理详情见 [清理清单](docs/cleanup_manifest.json)，完整备份位置见 [备份说明](cleanup_backup.json)。

记忆目录本轮清理了4项无人调用的旧实现。当前入口、共享底层和旧独立服务的区别，以及隐状态与来源论文的逐项对照，见 [记忆目录与隐状态核对](docs/memory_cleanup_and_latent_comparison_20260927.md)。

## 代码执行与前端状态

原分支20项代码功能样例已恢复。纯文本和协议字段均运行规划、检索、代码生成、实际执行、总结；通常4次模型调用，执行器不调用模型。代码格式错误最多修正一次，两组规则相同，额外调用和耗时如实计入。模型只收到题目、输入、允许的模块和结果字段名，不接收标准值或参考程序。评分比较实际程序执行结果，不执行参考代码来代替模型。五种方式均已有代码工具入口；隐状态还要求与代码任务匹配的离线查询校准，不能沿用问答映射。

文字和超图知识库来自同一组7个完整原文章节，共252条抽取事实。章节根据所选十轮文件中的来源标题取得，不按前三题答案裁剪；正文采用维基百科公开页面快照，不冒称原始评测年代的冻结知识库。原始网页、获取时间、校验值均保留，标准答案及人工标注片段不进入建库输入。离线抽取采用指定的 `qwen3.7-flash-2026-07-15`，原文复核纠正了7条把不利事件误标为否定的记录。

当前图检索按明确作品类型连接同名实体，按当前实体重新寻找记忆路径。关系目录只提供来源查找线索，不裁决答案充分性。隐状态仅在可达候选来源均已驻留时省去查库；相关关系包和路径不因固定行数而拆开。目录查询成本记入在线知识检索时间。

隐状态映射使用预备知识中的64个按关系分层选择的来源样本及通用问法进行校准，不使用正式题目或其参考答案，不修改基础模型权重。

协议保留原始问题，补充可追溯的指代对象。已检索到的完整来源字段由程序交接，模型不得重新抽取后替换它们；历史承接依据实际取得的来源，不依赖模型输出来源编号。来源与模型候选答案分开保存，候选答案不由程序依据参考答案改写。

当前运行由独立运行标识关联事件，历史回放须明确切换；任务分别显示等待、执行中、成功、失败、停止。未启动任务和旧结果不能标为本次完成。指标只比较同基础模型、后端、题目、知识来源及版本的完整运行；不把在线模型与本地小模型的时间混合比较。

第四版三题验证汇总见 [本轮验证报告](docs/verification_ranked153_20260927.md)，在线与本地分别比较。初轮、指代修复和字段交接修复的记录均保留，最终协议结果使用 `runtime/validation_v4_ranked153_protocol_v7`。前一版报告见 `docs/verification_20260927.md`；旧失败及最终结果仍保留在 `runtime/validation_v2`、`runtime/validation_v3`，不能与新数据直接比较。

第五版仅统一完整十题入口、前后端数量和服务器发布材料，不修改固定协作机制、知识库内容或校准映射。代码执行前端固定跑原库前十项；原二十项保留。服务器说明见 [服务器部署](docs/server_deployment.md)。


## 当前隐状态与校准

正式入口使用完整各层缓存直接续接，不执行额外末层反馈循环。新提示、新事实仍通过完整模型，各角色不生成中间文字；这不等于证明了连续隐推理适配。八候选和固定线性映射仅保留给实验，后者在本机入口检查中出现重复无意义输出，未采用为默认方案。历史成绩不能作为本版本成绩。

角色提示在直接下游完成后回收；内部连续步骤和边界在本题成功结束后回收。问题、来源事实、外部执行结果及最终答案跨题保留。保留位置的键值不变，旋转位置编码沿用原始逻辑位置，峰值包含裁剪临时分配。暂不支持裁剪的缓存布局保持完整状态并记录原因。该策略不等于对无限会话提供固定容量上限。

旧映射与新状态处理方式不兼容，不能仅更新哈希复用。每个模型、知识库、任务类型都需重新准备；服务器三模型的路径已切到独立的 `runtime/calibration-v73`，历史产物不覆盖。

```powershell
python -m tools.prepare_latent_readout --model 模型名称 --knowledge 知识库目录 --task-kind continuous --feedback-mode cache_only --latent-steps 0 --cache-policy consumer_lifetime --output 新校准目录
```

代码任务将任务类型改为 `codeact`。校准只使用预备知识和通用问法，不读取正式题目及答案。生成文件位于运行目录，上传项目或迁移服务器时需要单独携带或重新生成。

### 第7.6版记忆与输出修正

连续问答首轮来源范围与完整原文基线对齐：协议和隐状态实际读入同一来源语料的全部抽取事实，再写入会话证据记忆。首次字段读取及模型处理计入任务耗时，离线建图和校准单列。后续超图查询保留召回的关系、限定和来源，不按答案裁剪事实。

来源关系全部已收到时抑制同对象的重复知识库补查。未绑定代词保留给模型解释，其标记不再意味着同一记录必须再次读取；该检查仅核对来源成员，不裁决答案是否正确。字段统一来源内明确的实体身份，来源标题在独立表中传递一次。

隐状态最终解码同时识别模型和分词器的结束标记，并在官方模板开始下一条消息时结束当前输出。答案处理仅剥离真正位于开头的思考区，防止后续思考标记抹去先前答案。基础模型权重、完整缓存接续与评分规则保持原设置，小查询映射在新目录重校准，旧记录保留。

### 第7.7版协议记忆检索修正

协议先绑定当前问题的实体，再在已存关系中进行完整多跳召回。已绑定实体时不再无条件追加前两轮观察过的全部来源；只有无法绑定且检索没有结果时才使用前轮来源兜底。已召回关系、限定条件及来源全部保留，事实仍持续保存在记忆中。

来源使用六列字段和独立来源表；已经写入主体或客体的统一实体身份不再在限定字段里重复。隐状态特征计算代码及知识库未变，复用经哈希核验兼容的第7.6版离线校准。此次完整十题实验三组统一把输出上限从1024提高到3072，避免合理的长回答被截断，全部实际生成时间计入任务耗时。

### 第7.8版完整字段交接

协议检索角色仍读取全部召回关系、定位所需信息并判断缺口，但只生成缺口及补查请求，不再额外生成和传递事实解释。所有关系由程序原样交给推理与最终角色；模型原始输出仍保存于审计记录。已召回字段按来源分组、原文句序排列，关系、限定和来源不裁剪。三组回答要求、模型权重和解码参数不变，输出上限仍统一为3072；第7.7版的循环输出失败记录完整保留。

### 第7.9版共同输出保护

本地三组使用同一项输出保护：阻止本次生成重复已经生成过的32词元长片段。提示、来源和历史答案不参与去重，第一次复制原始证据不受限制；这项保护不裁剪输入，不读取评测答案，也不修改模型权重或模型方法。标准文本与协议仍通过官方生成接口，隐状态最终输出应用同一处理器。未受保护器干预的输出保持原始贪心选择。每次调用保存保护范围、长度以及阻止重复选择的次数，耗时完整计入。可用 `--output-repeat-ngram-size 0` 关闭以复现旧接口。

这是对三组相同的生成设置调整，不能把不同保护设置的成绩当成严格对照。当前默认长度为32，连续问答校准使用新的独立目录，旧版失败记录保留；查询特征源文件通过核验后才启用对应映射。

第7.9.1版仅修正命令行默认参数的后端兼容性：本地默认32，远程接口默认关闭本地输出保护。本次第7.9版完整十题实验均显式指定32，成绩及原始发布目录独立保留；该默认参数修正不改变本次显式参数路径的行为。
