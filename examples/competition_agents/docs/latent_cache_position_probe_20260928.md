# 角色交接时裁剪缓存并保持原始位置：三题验证

本次只选择缓存接续中的一个问题：裁剪缓存后，新状态的旋转位置编码不能直接从剩余缓存长度继续编号。独立实现和三题对照已完成，正式三条协作方案未改动。

结果：保留原位置的裁剪组按来源核对，三题所问人物均正确；完整接续快照累计从232.27降到153.52二进制兆字节，减少33.90%。键值缓存张量峰值包含裁剪临时分配，从44.73降到29.45二进制兆字节，减少34.18%。三题平均时间20.00秒对20.04秒，基本持平，没有证明稳定提速。

## 查到的问题与适用范围

核查的是论文官方仓库提交 `9a9e4d331eb11430bd9e64754c6b252b06d73031`：

- [可选缓存裁剪实现，第61行](https://github.com/Gen-Verse/LatentMAS/blob/9a9e4d331eb11430bd9e64754c6b252b06d73031/methods/latent_mas.py#L61)：截取缓存张量后重建缓存，未同时传递原始逻辑位置。
- [裁剪开关所在分支，第136行](https://github.com/Gen-Verse/LatentMAS/blob/9a9e4d331eb11430bd9e64754c6b252b06d73031/methods/latent_mas.py#L136)：可选地只保留本角色新增状态或连续隐步骤。
- [后续前向计算，第293行](https://github.com/Gen-Verse/LatentMAS/blob/9a9e4d331eb11430bd9e64754c6b252b06d73031/models.py#L293)：使用裁剪后的缓存长度，没有显式恢复被删位置对应的偏移。

对采用旋转位置编码的模型，保留下来的键仍携带旧位置编码。举例：原来已经处理100个位置，只留下最后10个位置的缓存；后续状态应接在原来的第101个位置，直接按剩余长度继续会把它放到第11个位置。缓存长度变短与逻辑时间回退是不同操作。

这是原仓库可选裁剪分支的问题，不是其默认完整缓存路径的问题。当前正式隐状态方案使用完整缓存，因此此前的速度波动不能归因于这个问题。本次没有运行原仓库的全部评测，也不据此声称其整套方法失效。

## 此次修改

代码仅位于独立实验目录：

- [实验实现](../experiments/latent_cache_position_probe.py)：在每个角色完成后尝试删除该角色的提示缓存，保持各层键值缓存的真实物理裁剪。
- [数值与边界检查](../experiments/test_latent_cache_position_probe.py)：验证位置接续、真实存储缩减、跨题事实保留和正式路径等价性。

裁剪选择规则在测试前固定：保留共同指令、所有问题、全部外部事实、连续隐状态、消息边界和最终答案；只删除已完成角色的提示缓存。所有角色首次仍读完全相同的提示，没有修改提示文本、基础权重或状态对齐方式。

修正将两个量分开：实际缓存长度用于存储和因果掩码；累计处理过的逻辑位置用于新的旋转编码。保留缓存的键不重新编号，接收方额外携带一个八字节的位置整数。已经删掉的旧提示缓存不再供下一角色读取。角色结束后的提示是否可删仍是需要任务验证的假设，不能因为保留两步隐状态就保证所有约束无损。

数学一致性检查以“完整缓存屏蔽被删位置”为参照，在连续后缀和不连续保留两种情形下，保持原始位置的后续模型输出在数值容差内一致；直接重新编号则不一致。这个检查验证的是位置正确性，不证明删除任意内容都安全。

## 对照设置

使用原来的真实连续问答数据第153号会话前三题，原顺序保持不变。模型仍为本地千问2.5十五亿参数模型，处理器四线程，基础权重冻结。四个角色、每个内部角色两步连续反馈、最终最多128词元均一致。

三组分别为完整缓存、相同规则裁剪后按剩余长度编号、相同规则裁剪并保留原始位置。三组各重复三轮，按循环顺序交替执行，组内跨题保留缓存，组间清空。所有运行完成后才读标准答案，没有依三题答案调整裁剪规则。

使用此前真实检索轨迹的固定事实回放，以隔离缓存机制。时间包括四个角色、事实首次编码、裁剪及最终生成，不包括模型加载、真实知识库检索、经验写回或网络传输，因此不是完整生产流程的成绩。

表中所有容量单位均为二进制兆字节。交接快照包含保留的全部层缓存、辅助张量和必要元数据；不是指针长度，也不是实际测得的网络流量。缓存峰值统计的是键值缓存张量，包含裁剪时新旧层短暂共存，不是整个模型或进程的内存峰值。

三轮各组回答完全一致。直接重新编号组在第三题把所问故事人物答成作品名称片段，因此确实答错；较少的输出词元不算成功提速。

保留原始位置组第二题回答了 `Cynthia Ann Stephanie Lauper`，标准答案的短称为 `Cyndi Lauper`。固定来源事实 `f70` 明确以人物身份字段连接这两个姓名，并说明其歌手身份，因此所问人物正确。原评分仍为部分匹配：它与短参考答案仅匹配姓氏，与长参考答案只匹配姓名部分。没有修改参考答案或评分器，83.33%的原结果完整保留，来源核对单列。该核对只判断所问人物和身份关系，不把所有附加措辞一并判定为正确。

完整缓存与位置修正组的新增输入、生成量及经过各层的位置数完全相同。收益来自旧缓存变少，而非减少这些首次前向计算。处理器环境中，缩小注意力可读缓存未带来稳定的总时间下降；不能只选择较好的中位数宣称提速。
