# 主流程与代码核查记录

日期：2026年10月1日。范围：比赛项目五种正式协作方式、连续问答与代码执行入口。前半部分记录初次静态核查，当时没有运行测试；文末追加用户授权后的真实实验发现、修复和验证，不能用原静态核查说明代替后续实验结果。

## 共用契约

角色职责、知识不足时的补查控制、生成设置、程序执行与评分流程集中维护。方法入口选择载体和记忆组织，不再各自编写一套角色判断。提示来自 `competition_agents/role_prompts.py`，流程来自 `competition_agents/unified_collaboration.py`。

已取得的来源事实与角色解释分开保存。来源字段不能被模型改写，旧答案始终标为未验证。检索和推理角色决定现有证据能否支持回答；经验只提示可尝试的关系路径，不能作为证据或充分性裁决。各方式使用相同补查预算。

## 不能由本次静态核查证明的部分

1. 没有运行验证，不能宣称本版准确率提高、耗时降低或所有模型已经适配。
2. 原始知识库未重建。程序保留已抽取、已召回的关系不等于证明抽取内容完整、语义正确，或检索能召回任何问题所需的全部信息。
3. 知识查询现已消费检索或推理角色返回的短查询，包含实体、目标关系和必要条件；隐状态从已生成词元中仅解码查询前缀。这里接通的是工具参数接口，没有把末层表示直接映射到图索引。查询的语义准确性、首查召回范围和空召回兜底的实际频率仍未运行验证；缺失参数的原题保底在记录中明确区分。
4. 当前隐状态路径使用完整缓存续接及内部词元生成，不启用旧末层反馈映射。中间生成计算仍存在；代码任务的程序仍需要文本交给执行器。
5. 本轮没有恢复活跃缓存的裁剪或有损压缩，只释放结束或切换的会话。不能声称已降低设备显存峰值。
6. 官方模板增量分离、缓存长度和布局有明确接口前提，必须在后续允许运行时逐模型核验。缓存恢复本身会产生重复计算，记录中必须保留，不能归作免费复用。
7. 记忆供给、未查库完成与答案覆盖度是不同统计；没有额外语义评审器判断每条记忆的因果贡献。经验记录也不登记未经验证的语义成功。
8. 角色交接消息、工具请求和返回、驻留状态和实际网络字节不能混为一个指标。工具载荷现已单列，因此不能与旧版把执行器消息算进交接量的统计混比。当前没有跨机器传输测量；驻留状态逻辑峰值不包含模型权重、设备分配器及全部临时张量。

## 第8.3版真实十轮发现及第8.4版修复

第8.3版三组均完成十轮，但隐状态出现会话标记续写。模型目录缺少 `generation_config.json`，文字配置只有结束词元248044（`<|endoftext|>`），官方分词器声明的消息结束词元是248046（`<|im_end|>`）。共用生成接口仅识别前者，因此模型即使已经结束当前消息，运行器仍让其生成下一轮用户与助手消息，造成异常输出和耗时。原十轮完整记录保留于 `outputs/v83-qa-20261001-233512-5618`。

独立诊断重现了前两个实际角色输出。同一逻辑前缀的完整计算与缓存接续前32个生成词元完全一致，均在正确句子后生成248046，再继续生成下一轮会话。这至少在该前缀中排除了“缓存不能理解”解释，但不能由一个前缀证明所有模型、所有位置数值等价。首词元分数有低精度数值差异，诊断原始记录保留。

第8.4版只修共用 `llm/generation.py` 的结束契约：同时识别模型生成配置与官方分词器的结束词元，使用官方分词器的填充词元，实际集合随每次调用记录。文本、协议和隐状态同改。没有按题截答案或加特殊提示，没有改模型权重、配置对象、记忆组织、活跃缓存或中间角色职责。新增真实小模型接口检查确认官方生成在消息结束处停止、发布配置与权重不变。合计10项针对性检查通过；第8.4版完整十轮使用独立目录复测。


## 第8.5版：只缩短在线编号，不压缩事实

第8.3版协议的实际输入共770640词元。在不调用模型的分词核对中，仅将原证据、文档及历史证据指针替换为可还原短号，计数变为180761词元，减少约76.5%。这不是模型实验成绩，也不能证明对应的耗时或覆盖度；它表明此前大量输入来自重复的64位审计编号。

修改 `collaboration_transport.py`：稳定地登记原编号与短号的一一映射，只投影事实行的编号与文档指针、来源表键、别名文档指针以及历史证据编号。姓名、关系、对象、极性、限定条件、来源标题及句序完整保留；相同字面值若出现在实体名、题目、答案、条件或程序输入中，不能替换。原文、完整文本记忆及检索索引不改。所有方式的共同历史元数据使用同一投影规则。

修改 `resident_chat.py` 和 `unified_collaboration.py`：短号跨角色、跨轮稳定，原历史签名用于避免重复编码，原编号映射计入驻留状态元数据并随结果保存。来源与记忆存储仍使用原编号；短号不代替完整关系内容，也不拿短号长度冒充隐状态载荷。

本机12项针对性检查通过，包括完整关系逐项还原、实体值与编号字面相同仍保留、程序输入不改、来源及整轮文本不压缩、稳定编号及官方消息结束契约。第8.5版与第8.4版使用独立发布目录，服务器原队列源码不变；完整三组十轮按同模型、同知识库、同职责文字和生成预算另行复测。
