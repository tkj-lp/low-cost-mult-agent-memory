# 按下游使用期限回收隐状态缓存：三题验证

已实现并测试独立候选：角色提示保留到直接下游完成，连续隐状态保留到本题回答完成，问题、来源事实、公共规则和最终答案跨题保留。无需额外模型调用或训练。正式三条方案没有替换。

结论：候选通过三题机制对照和真实检索链路核验，但没有全面优于上一版立即裁剪。它在三题结束后的缓存占用再减少5.33%，处理中缓存峰值却增加1.87%；答案没有观察到改善，时间差很小。当前证据支持“可以运行的状态期限管理原型”，不支持“明显提速或更准确”。

## 为什么这样修改

上一版直接删除刚完成角色的提示缓存，没有表示下游是否仍需要该角色的要求。新版本记录每段缓存的来源、所属角色、所属题目和到期阶段：

| 内容 | 保留期限 |
| --- | --- |
| 公共规则、问题及其中的用户约束、来源事实、最终答案 | 会话期间保留 |
| 规划角色提示 | 检索角色完成后释放 |
| 检索角色提示 | 推理角色完成后释放 |
| 推理角色提示 | 总结角色完成后释放 |
| 总结角色提示 | 本题回答结束后释放 |
| 内部连续隐状态和内部消息边界 | 本题回答结束后释放 |

期限由工作流明确声明，没有增加模型调用判断“这些内容是否已经没用”。未声明的状态类型拒绝静默回收；跳过应完成的消费者角色也会拒绝继续。角色执行失败时不执行其完成后的回收。

裁剪沿用原始逻辑位置，物理缓存长度和旋转位置编码分别处理。保留状态仍是已经计算好的各层键值缓存，没有重新转成文字输入。回收时确实缩小张量存储，并计入裁剪临时分配及处理时间。

这条规则有明确局限：本题结束不保证中间推导对未来问题毫无价值。保留问题、事实和答案，也不等于保留全部中间推导。当前没有自动识别隐状态中的语义依赖，不能把声明的期限称为无损性的证明。

## 固定证据的机制对照

使用原有真实连续数据第153号会话前三题及同一超图知识库。模型为本地千问2.5十五亿参数模型，处理器四线程，基础权重不变。四个角色、每个内部角色两步连续反馈、统一128词元输出上限和全部提示文本一致。

比较完整缓存、上一版立即裁剪、新版按下游期限回收三组。每组重复三轮、交替顺序运行，组内保留跨题状态，组间清空。测试题始终只有原来的三道。标准答案在全部运行完成后读取，没有依据测试答案改变期限规则。

此部分回放之前真实检索的相同来源事实，以隔离状态保留机制。时间包括四角色推理、事实首次编码、最终生成和回收开销，不包括真实检索、经验写回或模型加载。

三组在每次重复中都产生相同的各自答案。两个裁剪组第二题均返回人物全名 `Cynthia Ann Stephanie Lauper`。固定来源 `f70` 的人物身份字段明确连接该全名和参考答案简称 `Cyndi Lauper`，且说明其歌手身份。原评分仍为部分匹配，83.33%完整保留；来源核对只确认所问人物，不修改参考答案，也不把全部附加措辞都判为正确。

三次重复用于观察本机同三题的时间波动，不是九道独立任务。本次不做泛化显著性宣称。按下游期限回收比完整缓存平均仅少0.13秒，比立即裁剪平均少0.44秒，且上一版一轮存在较明显波动，不能据此宣称稳定提速。

## 为什么没有更大收益

新规则额外释放的内容只有18个连续隐状态位置和9个内部边界，共27个位置；其余问题、事实及答案继续保留。本地模型每个位置的全部层键值缓存为57,344字节，额外回收的理论量约1.48二进制兆字节。新版最终多生成一个词元，结束后实际比上一版少26个位置，即约1.42二进制兆字节。

与此同时，角色提示在消费者完成前多保留一个阶段，使峰值比上一版高约0.55二进制兆字节，逻辑注意力位置对数也多3.51%。生命周期规则更明确，但这三题没有证明其保护期带来了额外的回答收益。

与完整缓存相比，新版峰值低32.95%，结束后保留缓存低43.52%。这主要包含上一版已经取得的提示缓存裁剪收益，不能全部归功于本次新增的期限管理。

累计完整状态快照分别为232.29、153.54、162.06二进制兆字节，包含各自的期限管理元数据。它重复计入多个交接点的历史状态，不是实际通信载荷。三个方案均在同进程访问驻留缓存，本次没有测网络传输。

## 接回真实检索的功能核验

随后使用同样三题，接回正式的超图检索工具、原校准映射、事实记忆和经验读写。每组从独立空经验库开始，组内跨题保留。没有修改查询映射、检索门限或知识库，没有把回放事实直接送给模型。

| 指标 | 完整缓存 | 上一版立即裁剪 | 新版按下游期限回收 |
| --- | ---: | ---: | ---: |
| 角色模型调用次数 | 12 | 12 | 12 |
| 知识库检索次数 | 3 | 3 | 3 |
| 复用已编码事实条数 | 1 | 1 | 1 |
| 经验读取／实际采用 | 1／0 | 1／0 | 1／0 |
| 经验记录写入次数 | 4 | 4 | 4 |
| 三题完成时间，单轮功能检查 | 16.23秒 | 16.74秒 | 16.57秒 |

三组选择的来源编号逐题完全一致，答案也与机制对照一致。第二题确实复用了已编码事实，同时查询新需要的歌手身份事实。没有新增检索次数，也没有把经验“读取”算成“采用”。

上述单轮时间包含在线检索、记忆处理、经验写回和四角色调用，排除模型加载和静态索引准备。它与前面的三轮固定证据时间分开报告，仅用于核验链路可用，不作为稳定速度排名。

## 检查与采用结论

18项相关检查通过；181个固定文件核验不变。机制对照和真实链路核验均确认基础模型权重不变，哈希为：

完整缓存和立即裁剪两个对照，在数值检查中与上一轮实现得到相同的缓存张量。长期保留类型未被回收，事实未因删除缓存而被误标为可直接复用，消费者顺序和会话重置也经过检查。这些是实现正确性的检查，不代表复杂语义约束已经全面验证。

本次保留独立实验版本，不替换正式方案。尚未验证代码执行任务、更多真实约束、多会话长链和显卡环境；长期来源事实及问答仍随会话增长，未实现固定缓存容量上限。当前不将生命周期规则宣称为独立的新颖算法，也不把小样本功能通过写成广泛的准确率提升。
