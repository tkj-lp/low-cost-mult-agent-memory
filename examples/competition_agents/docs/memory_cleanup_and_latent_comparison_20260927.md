# 记忆目录清理与隐状态方法核对

## 目录为什么较大

该目录同时包含当前比赛方案、旧独立记忆服务、共享存储与剪枝底层、测试和旧工具。此前清理没有完整区分这几类文件，因此“文件还在”不能解释为“当前三条方案都在使用”。

本次以五个协作入口、代码工具入口、后台和离线建库/校准工具为起点，检查静态导入、函数引用、包入口导出及现有测试。清理前有41个顶层程序文件（含包入口，不含测试子目录），其中23个在当前入口的依赖闭包中，17个属于旧实现或旧接口，另1个是包入口。依赖可达不等于每次请求都会调用；包入口还会提前加载部分兼容模块，不能把实际导入与业务使用混为一谈。

## 与原论文的共同机制

核对来源为用户提供的《Latent Collaboration in Multi-Agent Systems》2025年版本，正文第3.1、3.2节、图3及附录A.1。

论文将末层表示经过对齐后作为下一步输入，内部角色不生成文字；跨角色共享全部层的键值缓存，缓存包含输入与已经产生的连续推理步骤；最后一个角色才解码最终答案。当前实现同样依靠这套思路。以下不能作为本项目原创贡献：

- 内部不输出文字、只有最终角色输出。
- 使用末层表示做连续推理。
- 通过各层键值缓存保留先前已计算内容，避免下一个角色重新计算旧前缀。

两者都不是把末层表示直接塞进模型中间某层实现跳层。当前 `_forward` 仍调用完整模型主体，新提示、新事实和新连续向量经过全部层。减少的是旧内容重复计算以及中间文字生成步骤。

## 当前已经实现的差异

| 层面 | 论文方案 | 当前实现 |
| --- | --- | --- |
| 连续状态对齐 | 从模型输入/输出权重求一次固定线性映射，后续复用 | 每步经输出分数选8个候选，以概率加权其输入向量并调整幅度，得到一个连续向量 |
| 外部知识检索 | 论文核心方法及主实验未包含本项目的超图知识检索闭环 | 将问题输入表示、问题末层表示和当前角色末层表示拼接，经过校准映射作为数值查询，检索实体关系路径 |
| 连续任务 | 展示一个任务内的多角色协作和工作记忆传递 | 同一会话跨题保留缓存，按来源编号和内容哈希避免重复编码已见事实；新问题、新事实仍首次输入 |
| 证据充分性 | 没有本项目的来源关系目录和缺口补查机制 | 检查必要关系及来源路径是否已取得；仅有高相似度或人物名不够时补查 |
| 经验 | 论文的工作记忆是计算状态，未包含当前检索路径经验层 | 根据实际检索轨迹积累路径策略；仅在候选省略上界检查通过时减少计算，带容量限制和剪枝 |
| 校准边界 | 其主方案无需额外数据训练 | 检索映射使用预备知识产生的样本做校准，基础模型不变，因此整体不能称为完全免训练 |

当前连续对齐的“8个候选混合”不同于论文，但差异本身不证明原创或更优。它每步仍计算词表分数，不是完全省掉输出层计算；其效果和耗时尚未与论文固定映射做同条件消融。检索映射与连续对齐是两个不同模块，不能混称为同一种适配。

实际代码对应：

- `competition_agents/llm/latent_only_chat.py`：全部角色接续、每层缓存、新事实去重、最终解码。
- `competition_agents/latent_hidden/posterior_alignment.py`：8候选连续混合对齐。
- `competition_agents/latent_hidden/calibrated_query.py`：数值检索映射校准。
- `competition_agents/latent_hidden/calibrated_graph_tool.py`：记忆优先、关系覆盖与补查。
- `competition_agents/latent_hidden/experienced_graph_tool.py`：经验路径选择和遗漏候选上界校验。
- `hypergraph_memory_method/retrieval_experience.py`：经验写回、容量约束与剪枝。

## 已实现与未证明的边界

当前更合适的定位是“基于隐状态协作的、支持连续任务和超图来源记忆的扩展原型”。新增机制主要在知识/记忆工具闭环，而不是另行发明缓存协作。

本机使用同一个模型实例、同一个驻留会话缓存。超图决定取得或复用哪些事实，目前没有依据超图关系裁剪缓存，也没有把完整上下文压成一个小向量后删除所有旧缓存。既有连续计算仍依赖保留的全部前缀。清空会话或更换模型后不能直接沿用这份计算状态。

最近三题中，第二题确实复用一条已编码事实；经验读取1次、采用0次。因此不能说经验已经贡献了提速。隐状态快照累计约232.27 MiB，驻留峰值约44.73 MiB，尚未测跨进程网络传输；不能宣称其字节载荷小于协议字段。

检索工具接收数值查询，但实体入口和关系覆盖目录仍使用原问题文本及规则辅助，不应描述为“整个系统每一步都只处理隐状态”。当前只与本项目文本、协议方案比较，未完成原论文实现的同条件对照和新增模块消融，不能据此宣称优于原论文或已经证明新机制的独立贡献。
