# 固定协作方案

当前版本：`competition-locked-v5-10turns`。运行入口只有 `run_competition.py`，前端通过 `runner_server.py` 调用同一个入口。

| 前端选项 | 记忆组织 | 记忆检索 | 实际交接内容 |
| --- | --- | --- | --- |
| 纯文本 | 普通文本 | 相似度 | 累积的完整原文、角色输出和所召回的整轮记忆 |
| 协议字段 | 超图 | 超图跳跃 | 模型直接生成的任务、事实关系、约束与必要来源字段 |
| 隐状态 | 超图 | 超图跳跃 | 同进程续接计算缓存和连续表示，仅最终输出生成文字 |
| AutoForm | 普通文本 | 相似度 | 模型自主选择格式生成的交接消息 |
| LLMLingua-2 | 普通文本 | 相似度 | 官方压缩模型处理后的交接消息 |

前三项是固定主要方案，后两项是保留对照。当前连续样本由用户指定截图中的 `data/official_factoid_ranked_topiocqa_003_10turns.json` 选取：第153号会话，原顺序完整十题。该窗口从原会话第一轮开始，后续涉及人物指代和作品话题承接；没有导入后续标准历史答案。题目已与官方原始文件逐字核验，来源说明见 `data/continuous_topiocqa_153_10turns_v1/provenance.json`。原三题目录保留用于历史复现。第119号会话及更早的小猫样本保留作历史记录。

纯文本记忆以完整一轮记录为相似度检索单元，不切句、不建立段落索引、不把命中内容再摘要。知识库仍保留完整原文；协议和隐状态读取预先建立的超图。三种实现拥有独立会话记忆，切换方案不会继承另一方案的状态。

协议的本地调用使用模型原生模板与生成接口，不加载隐状态、格式约束解码或跨角色缓存。现有隐状态映射只对应本地千问十五亿参数模型，不能直接切换模型或在线文字接口；基础模型权重保持不变。

隐状态经验层保留：从完成的检索中记录关系路径策略，在来源完整且遗漏候选的分数上界检查通过时缩小候选计算；否则回到完整检索。经验有数量上限与剪枝，不把参考答案写入经验，也不把检索等价性称为答案正确性验证。

## 指标边界

- 预备知识构建、校准和模型加载单列，不计入任务流程耗时；在线检索、角色处理、压缩和记忆写回计入。
- 文字方式报告真实交接消息的字节数；在线接口请求量与角色交接量不能混用。
- 隐状态报告每次交接所需的完整接续状态快照大小，包含各层缓存、隐藏表示及接续元数据。累计快照大小、缓存驻留峰值与网络实际传输是不同指标；同进程续接未进行网络传输实测，不能用引用长度或零字节证明载荷下降。
- 答案采用标准答案词元覆盖度；额外内容不扣分，少答部分计分。这不是自动事实核验，明确矛盾需要另做来源审查，不能把该分数直接称为事实正确率。
- AutoForm 目前每次交接额外调用同一模型转换格式，通常每题七次调用，转换时间全部计入。
- LLMLingua-2 必须加载官方模型，禁止以规则压缩兜底冒充该对照。

## 目录

- `competition_agents/methods`：五个独立入口和统一执行器。
- `config`：前后端共同方法配置、版本文件校验清单。
- `data`：连续任务、原始来源、固定预备知识和既有校准。
- `tools`：离线准备及固定版本核验工具。
- `hypergraph_memory_method`：底层记忆库。比赛运行入口只开放上述两种检索。
- `docs/evidence`：必要的历史原始结果，含失败与无提速对照。
- `docs/history`：历史报告，里面的旧运行路径不再作为当前入口。
- `runtime`：新运行产物，已排除出版本管理。

启动和复核见 [运行手册](RUNBOOK.md)。清理详情见 [清理清单](docs/cleanup_manifest.json)，完整备份位置见 [备份说明](cleanup_backup.json)。

## 代码执行与前端状态

原分支20项代码功能样例已恢复。纯文本和协议字段均运行规划、检索、代码生成、实际执行、总结；通常4次模型调用，执行器不调用模型。代码格式错误最多修正一次，两组规则相同，额外调用和耗时如实计入。模型只收到题目、输入、允许的模块和结果字段名，不接收标准值或参考程序。评分比较实际程序执行结果，不执行参考代码来代替模型。当前隐状态、两种额外压缩对照尚未接通此代码工具边界，选择代码任务时明确禁用。

文字和超图知识库来自同一组7个完整原文章节，共252条抽取事实。章节根据所选十轮文件中的来源标题取得，不按前三题答案裁剪；正文采用维基百科公开页面快照，不冒称原始评测年代的冻结知识库。原始网页、获取时间、校验值均保留，标准答案及人工标注片段不进入建库输入。离线抽取采用指定的 `qwen3.7-flash-2026-07-15`，原文复核纠正了7条把不利事件误标为否定的记录。

第四版新增来源范围内的作品类型消歧、明确所属连接、关系目录和证据覆盖检查。协议仍由原有模型调用理解问题，程序核对相应来源是否已取得；隐状态仍接收数值查询，利用同一关系目录检查驻留证据。目录查询成本记入在线知识检索时间，不以最高相似度或模型省略缺口字段代替完整性检查。未绑定来源会阻止充分性认证。当前目录使用通用规则识别部分关系类型，未知题型不能获得完整性认证；结构检查不是语义正确性的证明。

隐状态映射使用预备知识中的64个按关系分层选择的来源样本及通用问法进行校准，不使用正式题目或其参考答案，不修改基础模型权重。

协议的指代绑定只约束图检索入口，不把绑定实体拼进原问题。来源编号、文档编号、代码围栏等表示差异仅在可核实且无歧义时归一化。不存在的编号、被颠倒的支持关系会写入拒绝审计；只有原始来源字段已通过关系覆盖检查时，才隔离错误引用并把收到的必要关系原样交给下一角色。候选答案不由程序改写，未知题型或来源不足时仍返回失败，不增加修复模型调用。

当前运行由独立运行标识关联事件，历史回放须明确切换；任务分别显示等待、执行中、成功、失败、停止。未启动任务和旧结果不能标为本次完成。指标只比较同基础模型、后端、题目、知识来源及版本的完整运行；不把在线模型与本地小模型的时间混合比较。

第四版三题验证汇总见 [本轮验证报告](docs/verification_ranked153_20260927.md)，在线与本地分别比较。初轮、指代修复和字段交接修复的记录均保留，最终协议结果使用 `runtime/validation_v4_ranked153_protocol_v7`。前一版报告见 `docs/verification_20260927.md`；旧失败及最终结果仍保留在 `runtime/validation_v2`、`runtime/validation_v3`，不能与新数据直接比较。

第五版仅统一完整十题入口、前后端数量和服务器发布材料，不修改固定协作机制、知识库内容或校准映射。代码执行前端固定跑原库前十项；原二十项保留。服务器说明见 [服务器部署](docs/server_deployment.md)。
