# 共用角色流程与协作方式

当前代码版本：`competition-v8.16-bounded-role-fields-20261002`。

第8.16版进一步限定问答中间工作字段的规模：候选结论最多五百一十二个字符，依据最多三条、每条一百二十八个字符；规划实体最多八个、条件最多四项。所有文字协作方式共用这些类型界限。语法生成器合法闭合字段，不生成到预算尽头后再修半截对象。全部召回证据、来源、历史和最终回答预算保持完整；这些限制仅作用于角色新增工作，可能限制复杂任务的计划表达，需按实际答案覆盖度验收。代码任务的程序字段不使用这些界限。

五种协作方式、连续问答和代码任务统一进入 `competition_agents/unified_collaboration.py`。命令行入口为 `run_competition.py`，前端通过 `runner_server.py` 使用同一入口、预算和方法清单。第8.15版把语法兼容的重复保护接入问答角色字段生成，避免字段内重复证据编号耗尽预算；正式启用隐状态无用临时输出释放，任务写回后回收全部本题状态。各中间角色统一采用四十步隐式推理，不按题目调整。记忆、知识库、业务职责、评分、提示及上游核心冻结。各版真实成绩独立保留，不能拼接旧版本的最好成绩；本地接口回归不能替代真实模型成绩。

当前验证状态：现有千问3.5的同一组完整十轮中，文本209.00秒、覆盖99.09%，协议194.19秒、覆盖84.09%，隐状态四十步114.62秒、覆盖88.75%，均无流程或字段异常。十步隐状态更快，但覆盖度相对文本下降20.18%，因此最终默认选四十步。完整结果、十步对照和临时输出释放对照保存在 `outputs/protocol-bounded-fields-20261002/`。这是同一组十题上的工程配置选择，不是独立测试集或多模型的稳定性结论。MiMo此前重复输出尚未由本轮解决。

## 主流程

1. 从当前会话记忆读取历史与已观察的来源证据。
2. 规划角色解释当前任务和指代，提出检索计划。
3. 检索角色检查记忆与现有证据。认为够用就交付；认为缺少事实或关系才请求知识库，并给出包含已明确实体、目标关系和必要条件的短查询。搜索函数消费这个查询，返回的新证据交给同一角色继续检查。
4. 推理角色生成答案候选或程序。缺少证据可以提出补查，由检索角色继续处理。
5. 问答直接进入总结；代码任务先运行真实执行器，再让总结角色报告实际结果或错误。
6. 保存实际取得的来源事实；答案另作未验证历史。经验保存检索路径，不把回答或检索成功冒充语义正确性。

四个角色不表示每题一定只有四次调用。补查与一次程序格式修正会增加调用，次数与耗时全部记录。补查默认最多两次，预算用完仍交付已有内容和缺口，不能因此把证据标为充分或提前丢掉整题。

记忆是附加模块，也用于直接复用证据。检索、推理角色决定能否回答，程序不按“关系存在”“来源驻留”代替模型判断。关闭记忆后仍执行同一主流程；隐状态仅在本题角色之间续接，避免暗中跨题保留已关闭的记忆。

## 方法区别

| 方式 | 记忆与检索 | 下游获得的内容 |
| --- | --- | --- |
| 纯文本 | 完整一轮文本为相似度检索单元 | 当前任务、实际历史、召回的整轮记忆、完整来源原文、角色工作 |
| 协议字段 | 超图跳跃检索 | 相同任务与历史、原始实体关系和全部限定、独立来源表、角色工作字段 |
| 隐状态 | 与协议相同的超图记忆 | 同进程完整缓存与逻辑词元历史；新任务、证据、经验和工具结果增量输入 |
| AutoForm | 与纯文本相同 | 仅由格式转换插件转换角色工作；任务与来源原文保留 |
| LLMLingua-2 | 与纯文本相同 | 仅由官方压缩插件压缩角色工作；任务与来源原文保留 |

纯文本知识库整篇读取，不建立段落或答案片段索引；记忆相似度筛选不切分原文。来源原文在首次观察时存入整轮记忆，后续不会为了放大基线而每轮重复复制整库。

协议字段由程序从已准备的知识库记录组装，包含编号、原始主体、关系、对象、极性、全部限定、文档及来源句序，别名保持来源作用域。模型不重新生成事实表或来源编号，已召回的关系不在交接中再次裁短。问答角色使用共用的实体、目标、约束、候选结论和依据字段契约；协议直接解析本次输出，不额外调用抽取模型。完整历史供规划解析指代，规划明确给出实体和目标后，下游接收其字段，不再重复接收全部历史长答案。未知输出格式保留原文和历史回退并记录，不能冒充成功字段化。不同角色产生的新字段与修正均保留。

AutoForm 和 LLMLingua-2 是当前框架中的插件对照，转换范围已经明确为角色工作说明；不能与旧版压缩整段消息的实验混合比较，也不能声称本入口复现了其完整论文实验。

## 提示、格式与生成

所有方式的业务职责与最终答题要求来自 `competition_agents/role_prompts.py`，其职责不接收模型名或协作方式。隐状态只移除要求生成工作正文的文字接口，使用动作与查询接口，因此完整渲染提示不能声称逐字相同；职责和接口分别记录。固定公共规则位于开头的系统消息，本步角色职责和当前任务位于新增数据之后，中间动作规则只属于当前中间角色。

本地中间角色在官方生成接口下返回包含动作、查询和工作内容的完整对象，由 `lm-format-enforcer` 约束语法。在线后端使用对应的工具参数，同一类型校验器负责验证。交付携带本角色工作，查库携带非空查询，沿用不重复生成工作。规划只能交付计划。普通编号、错误类型、截断对象不能变成工具命令；异常原始工作保留并记录，主流程继续交接现有证据，不伪造一次查库决定。语法约束不保证判断或答案正确。

检索与推理角色的补查均使用实际返回的查询参数，不再固定使用原始问题。明确查询先重查已存记忆，新增的旧证据或完整文本单元交回角色判断；角色再次请求同一查询或没有新增信息时才查知识库。记忆重查不消费查库预算，同一查询在本轮不重复读取，初查及重查分别记录并累加时间。工具参数缺失时不增加格式修正调用，也不终止任务，而是显式记录异常及原题保底查询，不能把保底结果冒充规划后的查询。超图首查也按角色查询定位与跳跃检索，空召回才返回完整图来源；已召回关系不会在交接时再次裁剪。纯文本仍按原有约定提供完整原文，不新增段落索引或答案片段筛选。

全部本地方式的外部文字生成通过 `competition_agents/llm/generation.py` 调用模型官方 `generate()`；最终回答使用相同输出预算、贪心生成及可选重复保护。隐状态内部的连续表示使用上游前向循环，不经过选词和文本解码。结束规则共同识别模型配置和官方分词器声明的结束词元，防止生成配置文件缺失时漏认消息结束、继续生成下一轮会话；实际结束词元集合随每次调用记录。模型权重与发布配置对象不变。默认重复保护长度为三十二词元，仅检查本次输出，不检查提示、证据或历史答案，可以显式关闭。

模型返回的内容、原始词元、接口返回和诊断记录保留。缺少用量统计标为未知，不能撤回已成功生成的内容；控制或格式异常不会删除已经召回的证据。真实后端错误与空最终回答明确记录，不伪造成功。

## 当前隐状态的实际范围

正式入口为 `competition_agents/llm/latentmas_chat.py`。上游核心保存在 `competition_agents/vendor/latentmas/`，固定提交和兼容改动记录于其中的 `provenance.json`，保留原许可证。它保留完整各层缓存，新事实第一次输入后登记；同题已处理的证据不会再次前向。经验提示和外部执行结果通过同一增量输入契约提供。

每个中间角色使用上游岭回归映射、范数对齐和四十步连续表示推理；上游四个核心函数未改。内部请求使用模型默认聊天模板，不继承外部短回答的关闭思考选项，不在隐式推理后自行插入助手结束词元。完整各层缓存直接接给下一请求。工作正文不生成文字词元；外部检索生成明确的动作与查询，省去的只有工作正文字段，交付、查库、沿用的语义保持一致。代码交给执行器前仍需生成可执行程序，最终回答仍使用各方式共用的官方生成接口和相同答题要求。没有改变模型权重。

多模态模型的纯文本隐式推理通过 `LanguageForward` 访问原语言解码器，避免外壳残留的位置偏移与新增输入长度不一致。完整策略保留全部隐藏输出和原词表头分数，释放临时输出策略另行启用。两种策略都保留完整缓存；不会替换最终生成使用的原模型。回归覆盖实际多模态外壳、普通生成预热、多个角色续接，以及两轮记忆与代码执行交接。

本项目新增检索工具和连续任务记忆，角色职责也不同于上游的独立解题流程。因此这是上游核心在项目中的接入，不是原论文全部任务成绩的复现。默认完整缓存策略没有剪枝；可选临时张量释放策略只省去未被使用的输出，不减少有效键值缓存容量，不能把临时显存下降说成缓存压缩。

第8.15版默认使用 `release_transients`，完整各层缓存仍原样保留。`--latent-steps` 和 `--latent-memory-policy` 可显式覆盖默认参数并写入结果配置。重复保护在问答字段生成中先遵守语法掩码，保留合法闭合或转义；不裁剪输入事实，不在生成结束后偷偷删除工作内容。代码任务的程序正文不应用新增的字段重复保护。每题峰值从上一题回收后的实际驻留量重新计量。

共同规则的前缀状态独立保留，后续只追加当前职责和新输入。模型核对证据后可以选择沿用已有工作；沿用对象没有新的工作正文。每个角色仍实际调用模型，不固定跳过规划、检索或推理。分词器语法索引与模型一起加载，准备时间不混入逐题生成耗时。

本地调用记录输入前向、后续生成前向和官方生成总耗时，显卡前向通过事件计时；隐状态额外记录新增输入前向与缓存收尾。计时钩子在生成结束或异常后移除，不改变权重、前向实现或发布配置。这些分项有包含关系，不可全部相加当作任务总耗时。

最终角色提示不包含中间控制或字段输出规则。规划必须为当前任务产生计划；没有来源证据时不能选择沿用，首次推理必须产生候选，代码推理必须交付实际程序。满足这些动作前提后，是否沿用仍由模型判断，不由程序宣称证据充分。

同一题内完整保留各层缓存，不按角色盲删或压缩。任务结束且事实、来源及回答历史已写入记忆后，`TaskStateLifecycle` 回收本题工作状态，恢复独立保存的公共前缀；记忆写入失败时不回收。下一题通过记忆检索取得旧证据并重新编码，不能把这种跨题记忆复用统计成跨题缓存复用。公共前缀副本计入状态空间。混合注意力恢复真实前缀副本，不把递归状态假装裁短。

每次前向和生成另行检查模型声明的上下文容量，给消息结束片段留出位置。剩余容量不足时降低本次输出上限并记录；完整输入本身超限时明确报告容量错误，禁止删除证据后冒充完整输入。任务寿命回收不能代替上下文容量检查。

缓存异常时保留已提交词元及真实连续向量，尝试重建，并记录重复计算与恢复诊断；连续位置对应的占位词元不能被拿来替代真实向量重算。各模型的真实答题能力仍需运行验证；逐层缓存一致性和接口回归不能证明语义正确。

## 数据与评分

- 连续问答：TopiOCQA 第153组原顺序完整十轮，公开问题为 `data/continuous_topiocqa_153_10turns_v1/questions.json`。标准答案仅供输出后评分，不进入模型输入。
- 问答知识库：`data/prepared_knowledge/topiocqa_153_v4`，文本与超图来自相同七份公开原文、二百五十二条离线抽取事实。建库不读取标准答案；本轮没有更换数据或重建知识库。
- 代码任务：仓库 `data/codeact_tasks.json` 二十项功能任务，默认前十项，不称为官方公共代码智能体基准。模型只收到任务、输入、允许模块及结果结构，不接收参考值或参考程序。
- 问答按标准答案覆盖度计分，多回答不直接扣分，漏答部分得分；词面覆盖不是语义正确性证明。
- 代码按实际执行返回的结果计分。执行器的失败结果仍进入总结，不执行参考程序替代模型工作。

## 指标口径

任务完成耗时包含角色调用、检索、记忆写入、消息转换和实际执行；模型加载与图索引准备单列。每个失败调用也计次数和已发生耗时。流程是否走完、回答覆盖度、代码执行是否成功分开记录，不能把答错当作流程没有运行。

纯文本、协议与压缩插件记录实际序列化的角色交接消息大小。外部检索和执行的请求、返回单独记录工具消息大小，检索查询和结果还分别记录字节数，不能把知识库返回量混进智能体交接载荷。隐状态记录可续接状态的缓存张量、保留表示、六十四位词元历史和元数据大小，不把对象索引长度当作完整载荷。同进程状态未通过网络发送，网络传输量为未知。状态逻辑峰值不等于设备总显存或临时张量峰值。

记忆证据供给表示旧证据进入本轮角色输入；纯记忆完成表示本轮没有查库且流程走完。这些计数不能证明模型在语义上采用了哪条记忆。经验只提供提示，没有程序自动判定证据充分性，也不登记未经验证的语义成功。

协议在线别名表保留对应名称、文档作用域、来源句定位和作用域标记；抽取解释与完整引用仍保存在预备知识库及审计记录，不逐次重复交给角色。事实行、极性、限定和来源不裁剪。在线证据编号、文档编号及历史证据指针使用稳定的一一对应短号；原编号留在存储、检索和审计，映射随结果保存，并计入隐状态元数据载荷。实体名称、关系、对象、限定、问题和答案不做编号替换；纯文本的原文与整轮记忆不压缩。各方式的共同历史元数据使用同一规则，没有修改职责提示内容。

详细修改理由、代码位置和核验范围见 [本轮代码核查](docs/shared_workflow_review_20261001.md)。旧说明及历史实验解释见 [改动前说明](docs/history/readme_v80_before_shared_workflow.md)。各版真实十轮成绩独立保留：第8.2版隐状态没有有效成绩，第8.3版暴露漏认消息结束词元的问题，第8.4版统一修复结束契约，第8.5版再以可还原短号替换在线长编号。每版运行目录及配置独立保存，不能混合版本或覆盖旧成绩。
